# 奖励函数非线性改进方案

> 创建时间：2026-07-03
> 对应模型：`mymodel_reward_v2`

---

## 问题背景

当前 `mymodel_reward_v2/env.py` 中所有奖励函数均为**线性加权求和**形式：

```
reward = α₁·f₁(x) + α₂·f₂(x) + α₃·f₃(x) + ... + αₙ·fₙ(x)
```

具体体现：
- **势函数塑形**: `γ·Φ(s') - Φ(s)` — 一阶差分
- **终端奖励**: `scale × F1 + bonus - penalty × count` — 纯线性
- **步骤奖励**: `base + scale × ΔF1 - penalty × count` — 纯线性
- **好奇心奖励**: `bonus × score × rarity` — 多项式乘积但仍是线性组合
- **多选惩罚**: `penalty × over_select` — 线性

**完全没有**用到：
- 对数/指数衰减
- sigmoid/softmax 非线性门控
- 二次/高阶惩罚
- 边际效用递减
- 信息论度量（熵、KL散度）
- 对比学习式的相对奖励

---

## 改进方案一：边际效用递减的 F1 奖励

### 当前代码（`_set_potential` 第306-309行）

```python
f1 = set_f1(selected_Se, self.piece_Se)
return cfg['potential_scale'] * (f1 - cfg['potential_baseline']) - cfg['cardinality_penalty'] * cardinality_error
```

### 改为

```python
f1 = set_f1(selected_Se, self.piece_Se)
# 对数边际效用递减: F1从0.5→0.6的奖励增量 > 0.8→0.9的增量
f1_transformed = np.log(1 + 9 * f1) / np.log(10)  # 映射[0,1]→[0,1]，低F1区梯度更大
return cfg['potential_scale'] * (f1_transformed - cfg['potential_baseline']) - cfg['cardinality_penalty'] * cardinality_error
```

### 数学原理

使用对数变换函数 `f(x) = log(1 + 9x) / log(10)`，在 `[0, 1]` 区间上是一个凹函数（concave function），满足边际效用递减：

- 在低 F1 区域（0.0–0.3），梯度较大，每一步改进都能获得显著奖励
- 在高 F1 区域（0.7–1.0），梯度较小，需要更大努力才能获得同等奖励增量

### 效果对比

| 原始F1 | 变换后F1 | Δ变化 |
|--------|----------|-------|
| 0.0 | 0.00 | - |
| 0.3 | 0.62 | +0.62 |
| 0.5 | 0.79 | +0.17 |
| 0.7 | 0.90 | +0.11 |
| 0.9 | 0.96 | +0.06 |
| 1.0 | 1.00 | +0.04 |

**优点**：
- 低 F1 区域的每一步改进获得更大奖励，鼓励模型在早期快速学习
- 高 F1 区域改进边际递减，避免模型只优化高频标签而忽略稀有标签
- 函数仍保持单调性，不会改变奖励的方向性

## 改进方案二：二次惩罚过度选择

### 当前代码（`_macro_step_reward` 第455-456行）

```python
over_select = max(0, len(next_selected_Se) - len(self.piece_Se))
reward -= cfg['over_select_penalty'] * over_select
```

### 改为

```python
over_select = max(0, len(next_selected_Se) - len(self.piece_Se))
# 二次惩罚: 多选1个惩罚1x，多选2个惩罚4x，多选3个惩罚9x
reward -= cfg['over_select_penalty'] * (over_select ** 2)
```

### 数学原理

二次惩罚函数 `f(x) = α·x²` 是一个凸函数（convex function），满足边际惩罚递增：

- 少量多选（1-2个）：惩罚相对温和，给予一定的容错空间
- 大量多选（3+个）：惩罚指数增长，强力抑制"撒网式"预测行为

### 效果对比（设 `over_select_penalty=0.08`）

| 多选数 | 线性惩罚 | 二次惩罚 | 差异 |
|--------|---------|---------|------|
| 1 | -0.08 | -0.08 | 相同 |
| 2 | -0.16 | -0.32 | **2倍** |
| 3 | -0.24 | -0.72 | **3倍** |
| 5 | -0.40 | -2.00 | **5倍** |
| 10 | -0.80 | -8.00 | **10倍** |

**优点**：
- 少量多选容忍，大量多选重罚
- 符合医学诊断场景：多开 1-2 个检查可以接受，但多开 5 个以上属于过度医疗
- 数学形式简洁，不需要引入新的超参数

## 改进方案三：对数稀有度权重

### 当前代码（`data.py` 中 `compute_Se_weights` 函数，幂函数形式）

```python
# 当前使用 power=0.85 的幂函数压缩
weight = (max_count / count) ** power  # 如 (1000/2)**0.85 ≈ 195
```

### 改为（对数压缩）

```python
# 对数压缩: support=2的标签权重从~195降到~log(500)≈6.2
weight = 1 + np.log(1 + max_count / count) * scale
# 例如: count=2, max_count=1000 → weight = 1 + ln(501) * 0.5 ≈ 4.1
```

### 数学原理

对数函数 `f(x) = 1 + ln(1 + x)` 增长极其缓慢，具有最强的压缩效果：

- 支持度极低（如 count=2）的标签权重被大幅压缩（从 ~195 降到 ~4.1）
- 支持度中等（如 count=50）的标签权重也被压缩（从 ~13 降到 ~2.0）
- 不同稀有度的标签之间的权重差异被缩小，避免极端值主导训练

### 效果对比（`max_count=1000`，`scale=0.5`）

| Support | 当前幂函数权重 (power=0.85) | 对数权重 | 差异 |
|---------|---------------------------|---------|------|
| 2 | ~195 | ~4.1 | **47x 缩小** |
| 5 | ~90 | ~3.5 | **26x 缩小** |
| 10 | ~50 | ~2.8 | **18x 缩小** |
| 50 | ~13 | ~2.0 | **6.5x 缩小** |
| 100 | ~7 | ~1.7 | **4x 缩小** |
| 500 | ~2 | ~1.2 | **1.7x 缩小** |
| 1000 | ~1 | ~1.0 | 相同 |

**优点**：
- 对数压缩让稀有标签权重从极端值（195）降到合理范围（4.1）
- 避免稀有标签主导整个奖励信号
- 维持了"越稀有越重要"的排序关系（单调性不变）
- 数值稳定性更好，不会出现因极端权重导致的梯度爆炸

## 三个改进的联合效果

以 `tail_cost_curiosity` 模式为例，**步骤奖励**的完整变化：

### 当前

```
reward = γ·Φ(s') - Φ(s) - 0.008（步惩罚）
         + 0.40·稀有度 × max(0, weight-1)（稀有TP奖励）
         + 好奇心奖励
         - 0.36·FP惩罚
         - 0.08·多选数
```

### 改后

```
reward = γ·Φ'(s') - Φ'(s) - 0.008（步惩罚）
         + 0.40·稀有度_对数 × max(0, weight_对数-1)（稀有TP奖励，权重更合理）
         + 好奇心奖励
         - 0.36·FP惩罚
         - 0.08·(多选数)²（二次惩罚）
```

其中 `Φ'(s)` 是对数变换后的势函数：

```
Φ'(s) = 1.60 × [log(1+9·F1)/log(10)] - 0.03 × 数量误差 - 0.34 × 漏选率 + 好奇心势能
```

### 核心改变

| 改进 | 数学形式 | 解决的问题 |
|------|----------|-----------|
| 边际效用递减 F1 | `log(1 + 9·F1) / log(10)` | F1 越高，每点改进的奖励增量越小，避免模型只优化高频标签 |
| 二次多选惩罚 | `(over_select)²` | 少量多选容忍，大量多选重罚，防止"撒网式"预测 |
| 对数稀有度权重 | `1 + ln(1 + ratio)` | 极端稀有度权重被压缩到合理范围，不会主导训练 |

## 其他可考虑的数学建模方向（未实现）

| 改进方向 | 数学形式 | 解决的问题 |
|----------|----------|-----------|
| Sigmoid 门控惩罚 | `penalty = σ(over_select - k)` | 多选惩罚在少量多选时应宽松，超过阈值后急剧增大 |
| 熵正则化 | `R += λ·H(policy)` | 鼓励探索，防止策略过早坍缩到常见标签 |
| 对比式 F1 势能 | `Φ(s) = F1(s) / (1 + F1(s))` | 非线性压缩 F1 值，使低 F1 区域梯度更大 |
| 余弦退火探索奖励 | `bonus × cos(π·progress/2)` | 探索奖励随训练进展自然衰减 |
| 马太效应 | `reward = base + γ·accumulated_reward` | 对持续正确的标签累积奖励，形成正向反馈 |

## 实现注意事项

1. **需要同步修改的文件**：
   - `syj/lhz/mymodel_reward_v2/env.py` — 改进一、改进二
   - `syj/lhz/mymodel_reward_v2/data.py` — 改进三（如果有 `compute_Se_weights` 函数）

2. **超参数影响**：
   - 改进一：对数变换在 `[0,1]` 区间是凹函数，可能需要微调 `potential_scale` 和 `potential_baseline`
   - 改进二：二次惩罚使惩罚值增大，可能需要降低 `over_select_penalty`（如从 0.08 降到 0.04）
   - 改进三：`scale` 参数（建议初始值 0.5）控制对数压缩的强度

3. **实验验证建议**：
   - 先在消融实验中逐个开启改进，验证每个改进的独立效果
   - 再联合开启所有改进，验证组合效果
   - 对比指标：稀有标签召回率、整体 F1、假阳性率
