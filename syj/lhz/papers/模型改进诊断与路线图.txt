================================================================================
二、改动不到位之处（详细诊断）
================================================================================

【问题1】potential_f1 奖励模式不是真正的"F1数学化奖励塑形"

  现状：
  - _set_potential() = potential_scale * F1 - cardinality_penalty * error
  - _potential_step_reward() = γ * Φ(s') - Φ(s) - step_penalty
  - 本质是把 F1 当势函数做 PBRS（Potential-Based Reward Shaping）

  不足之处：
  a) 没有像论文2（ICLR 2023, "Deep RL for Cost-Effective Medical Diagnosis"）
     那样基于 F1 的分数线性规划性质和对偶优化理论来设计奖励。论文2的核心贡献是
     将 F1 优化转化为可证明的 RL 目标，有理论保证。当前实现缺少这种数学基础。
  
  b) 势函数中 potential_scale=1.0 是手工设定的默认值。根据论文5
     （"Improving PBRS Effectiveness", AAMAS 2025），势函数的线性平移可以显著
     影响 PBRS 效果，当前没有做这方面的调优。
  
  c) 势函数中的 cardinality_penalty=0.08 是手工经验系数，没有像论文4（BSRS,
     AAAI 2025）那样用 Value Network 的输出自动充当势函数。

  改进建议：
  - 阅读论文2的开源代码（GitHub: Zheng321/Deep-Reinforcement-Learning-for-
    Cost-Effective-Medical-Diagnosis），理解其 reward_shaping 实现
  - 对势函数做线性平移实验：Φ'(s) = Φ(s) - baseline（baseline 可取训练集平均F1）
  - 长期可考虑用 Dueling DQN 的 Value Stream 输出 V(s) 作为势函数（BSRS）

【问题2】优先经验回放(PER)的数据结构不够高效

  现状：
  - 使用 deque + np.random.choice 实现优先级采样
  - 每次采样复杂度 O(n)，其中 n 是 memory 容量

  不足之处：
  - 当 ReplayMemory 容量较大（如 50000+）时，np.random.choice 会成为性能瓶颈
  - Rainbow DQN 和 dopamine 的标准实现使用 SumTree 数据结构

  改进建议：
  - 用 SumTree 替换 deque + np.random.choice
  - SumTree 实现 O(log n) 的采样和优先级更新
  - 参考 dopamine 的 SumTree 实现或 stable-baselines3 的 PrioritizedReplayBuffer

【问题3】SetAwareDuelingDQN 缺少排列不变性训练

  现状：
  - SetAwareDuelingDQN 将症状和已选证候要素分路编码，在 joint 层用逐元素乘法融合
  - 训练时通过 pretrain_all_permutations 做数据增强来缓解顺序依赖

  不足之处：
  - 论文9（"Deep Reinforced Sequence-to-Set", 2018）专门设计了机制消除顺序依赖，
    核心思想是让 RL 框架显式建模"无序性"，而非仅依赖数据增强
  - 当前做法不能保证模型在任意输出顺序下得到相同的集合结果

  改进建议：
  - 对同一病例生成多个随机排列的轨迹，对所有排列的 Q 值取平均作为最终 Q 值
  - 或在损失函数中加入排列不变性正则项：L_inv = ||Q(perm1) - Q(perm2)||²
  - 参考论文9的 Order-Agnostic 训练方法

【问题4】辅助监督损失权重使用不够精细

  现状：
  - aux_supervised_weight 固定为 0.05

  不足之处：
  - 资料建议（改进方向2.6）：训练初期使用较大的辅助损失权重（如 0.5），
    后期逐步衰减到 0.05，以在 RL 训练早期更好地保留预训练知识
  - 固定权重无法适应不同训练阶段的需求

  改进建议：
  - 使用衰减权重：aux_weight = aux_start * (1 - progress) + aux_end * progress
  - 例如 aux_start=0.5, aux_end=0.05
  - 或在每个 episode 内部按病例难度动态调整

【问题5】目标网络更新机制的一个细节问题

  现状：
  - target_update_interval 默认 250 步（基于 optimization_steps 计数）
  - 同时有 optimize_interval=5（每5步优化一次）
  
  潜在问题：
  - 当前 target_update_interval 是基于 optimization_steps 而非 transition_steps
  - 这可能导致目标网络更新频率与预期不符
  - 论文7（"Double vs Dueling DQN Transfer"）发现 Dueling DQN 在更新频率不当时
    存在显著的不稳定性

三、缺少的关键改进（按重要性排序）
================================================================================

【缺失1】🔴 噪声网络（Noisy Networks）—— 最重要缺失

  来源：Rainbow DQN（论文1）、BTR（论文3）
  重要性：★★★★★

  为什么重要：
  - 当前使用 epsilon-greedy 探索，对所有状态做相同程度的随机探索
  - 辨证场景的状态是稀疏二值症状向量，不同症状组合需要不同程度的探索
  - Noisy Nets 实现状态依赖探索：网络自动学习对不同病例应该探索多少
  - 对稀有证候要素的探索更有针对性，比 epsilon-greedy 更智能

  实现要点：
  - 将网络中的 Linear 层替换为 NoisyLinear
  - NoisyLinear: weight = mu + sigma * epsilon
    mu 和 sigma 是可学习参数，epsilon 是每次前向传播时采样的随机噪声
  - sigma_init 建议设为 0.017（Rainbow 论文推荐值）
  - 噪声参数通过梯度下降自动学习，不需要手动调 epsilon 衰减曲线

  预期效果：
  - 提升稀有证候要素的召回率
  - 改善探索效率，可能提升 exact_match
  - 在复杂状态空间中特别有效

【缺失2】🔴 课程学习（Curriculum Learning）—— 论文8证明对Dueling DQN至关重要

  来源：论文8（"Curriculum Dueling DDQN", 2025）
  重要性：★★★★★

  为什么重要：
  - 论文8的消融实验明确证明：不用课程学习会导致 Dueling DQN 训练崩溃
  - 标准 DQN 在此任务中无法学习有效策略
  - 你的消融实验中 Full 模型 exact_match=0.5073（只有一半病例完全正确），
    可能是训练不稳定的表现
  - Pretrain Only 反而比 Full 好（0.5806 vs 0.5073），说明 RL 阶段损害了预训练

  实现要点：
  - 按真实证候要素数量对训练样本分组
  - 阶段1（前30% episodes）：只用 1-2 个证候要素的病例
  - 阶段2（30%-60% episodes）：加入 3-4 个证候要素的病例
  - 阶段3（60%-100% episodes）：全量数据
  - 或者在每个 episode 内按难度渐进采样（从简单病例开始，逐步混入复杂病例）

  预期效果：
  - 训练稳定性显著提升
  - 减少灾难性遗忘
  - 提升复杂病例（证候要素多）的预测精度

【缺失3】🔴 Multi-step Learning —— 对长序列辨证特别重要

  来源：Rainbow DQN（论文1）
  重要性：★★★★

  为什么重要：
  - 当前使用单步 TD 目标：只考虑即时奖励
  - 辨证过程是顺序选择证候要素，对证候要素多的病例（如 5-6 个），
    单步奖励信号传递很慢
  - n 步回报能更快地将"最终F1高"的奖励信号传递到早期选择步骤

  实现要点：
  - 目标改为：R_t^(n) = sum_{k=0}^{n-1} gamma^k * r_{t+k} + gamma^n * max_a Q(s_{t+n}, a)
  - 建议 n=3（在辨证场景中对应连续选择 3 个证候要素）
  - 需要在 memory 中存储 n 步轨迹，或使用 n-step replay buffer

  预期效果：
  - 加速奖励信号传播
  - 对长序列病例的学习效果更好
  - 提升 sample_f1 和 exact_match

【缺失4】🟡 真正的 F1 奖励塑形框架（论文2 SM-DDPO）

  来源：论文2（ICLR 2023）
  重要性：★★★★

  为什么重要：
  - 论文2 的方法有理论保证（可证明地找到 Pareto 最优策略）
  - 你当前的 potential_f1 只是经验性的 PBRS，缺少理论支撑
  - 论文2 的 SM-DDPO 框架专门针对医学诊断场景设计

  实现要点：
  - 利用 F1 的分数线性规划性质
  - 引入拉格朗日乘子处理预算约束
  - 参考其 GitHub 开源代码

【缺失5】🟡 停止机制的置信度学习

  重要性：★★★

  为什么重要：
  - 当前停止机制：网络选择 stop_action 即停止
  - 更好的做法：让网络学习一个置信度阈值
  - 当所有未选标签的 Q 值都低于阈值时自动停止
  - 或引入专门的"停止 Q 值"，让网络学习"继续选 vs 停止"的最优权衡

  实现要点：
  - 在奖励函数中为过早/过晚停止设计差异化惩罚
  - 或者在网络输出中加入 stop_value 头，独立学习停止决策

【缺失6】🟡 BSRS 自举式奖励塑形（论文4）

  来源：论文4（AAAI 2025）
  重要性：★★★

  为什么重要：
  - 用 Dueling DQN 的 Value Stream 输出 V(s) 作为势函数
  - 塑形奖励 F(s,a,s') = gamma * V(s') - V(s)
  - 可以自动化奖励塑形，减少对手工奖励超参数的依赖

【缺失7】🟡 动态奖励缩放（论文6）

  来源：论文6（IEEE AIxSET 2025）
  重要性：★★

  为什么重要：
  - 训练初期可能更需要探索性奖励，后期更应强调精确匹配
  - 可以让各奖励项权重随训练进度自适应调整

四、消融实验暴露的问题
================================================================================

消融实验结果（20260629_170450 批次，auto 模式）：

| 实验                    | sample_f1 | exact_match | micro_f1 | avg_cardinality_error |
|------------------------|-----------|-------------|----------|----------------------|
| Full                   | 0.8790    | 0.5073      | 0.8888   | 0.5110               |
| w/o Pretrain           | 0.8692    | 0.4451      | 0.8799   | 0.5769               |
| Pretrain Only          | 0.8887    | 0.5806      | 0.8993   | 0.3278               |
| w/o Expert Warmup      | 0.8826    | 0.5147      | 0.8918   | 0.4579               |
| RL Only                | 0.8618    | 0.4524      | 0.8735   | 0.6136               |

关键发现：

【发现1】🔴 RL 训练存在灾难性遗忘（Catastrophic Forgetting）
  - Pretrain Only 的 sample_f1=0.8887，Full=0.8790 → RL 反而降低了 F1
  - Pretrain Only 的 exact_match=0.5806，Full=0.5073 → RL 让完全匹配率下降 7.3 个百分点
  - Pretrain Only 的 cardinality_error=0.3278，Full=0.5110 → RL 让基数误差增大 56%
  - 结论：当前 RL 训练正在损害预训练阶段学到的知识

  可能原因：
  a) RL 阶段学习率过大，覆盖了预训练权重
  b) epsilon-greedy 探索产生的低质量轨迹污染了经验池
  c) 奖励函数信号不够精确，引导策略偏离最优方向
  d) 缺少课程学习导致训练不稳定

  解决方案：
  - RL 阶段使用较小的学习率（预训练 lr 的 1/5 ~ 1/10）
  - 加入弹性权重巩固（EWC）正则项，保护预训练学到的重要权重
  - 增大辅助监督损失权重（训练初期 0.5，逐步衰减到 0.05）
  - 引入课程学习，先训练简单病例

【发现2】🟡 专家轨迹预填充贡献有限但为正向
  - w/o Expert Warmup vs Full: sample_f1 从 0.8790 → 0.8826（略有提升）
  - exact_match 从 0.5073 → 0.5147（略有提升）
  - 说明专家轨迹预填充对 exact_match 有正面作用，但影响不大

【发现3】🟡 监督预训练贡献最大
  - w/o Pretrain vs Full: sample_f1 下降 0.0098，exact_match 下降 0.0622
  - RL Only vs Full: sample_f1 下降 0.0172，exact_match 下降 0.0549
  - 监督预训练是当前模型性能的最大贡献者

【发现4】🔴 DQN 在 exact_match 和 macro_f1 上明显落后

  解决方案：
  - 噪声网络替代 epsilon-greedy → 提升稀有标签探索
  - PER 已实现 → 稀有标签的高 TD-error 经验会被优先回放
  - 考虑在奖励函数中对稀有证候要素加权

【发现5】🟡 DQN 的 sample_f1 与树模型差距不大
  - DQN=0.8790 vs RF=0.8975 vs HGB=0.9051
  - 差距在 2-3 个百分点，属于可追赶范围
  - 加入噪声网络和课程学习后有望追平或超越

【发现6】🟢 DQN 在 cardinality_error 上与树模型接近
  - DQN=0.5110, RF=0.3425, HGB=0.3297
  - avg_selected_count: DQN=3.27, RF=3.47, HGB=3.51
  - DQN 选择的证候要素数量更接近真实值（3.56）

第二阶段：核心改进（3-5天）

【任务2.1】🔴 噪声网络（Noisy Networks）—— 最高优先级
  - 实现 NoisyLinear 层：
    class NoisyLinear(nn.Module):
        def __init__(self, in_features, out_features, sigma_init=0.017):
            super().__init__()
            self.mu_weight = nn.Parameter(torch.Tensor(out_features, in_features))
            self.sigma_weight = nn.Parameter(torch.Tensor(out_features, in_features))
            self.mu_bias = nn.Parameter(torch.Tensor(out_features))
            self.sigma_bias = nn.Parameter(torch.Tensor(out_features))
            self.reset_parameters()
            self.register_buffer('epsilon_weight', torch.Tensor(...))
            self.register_buffer('epsilon_bias', torch.Tensor(...))
        
        def forward(self, x):
            # 每次前向传播重新采样噪声
            self._sample_noise()
            weight = self.mu_weight + self.sigma_weight * self.epsilon_weight
            bias = self.mu_bias + self.sigma_bias * self.epsilon_bias
            return F.linear(x, weight, bias)
  
  - 将 SetAwareDuelingDQN 中的 Linear 层替换为 NoisyLinear
  - 移除 epsilon-greedy 探索（或用极小的 epsilon 做安全网）
  - 文件：model.py, action.py

【任务2.2】🔴 课程学习（Curriculum Learning）
  - 按真实证候要素数量对训练数据分组
  - 在 train() 中实现三阶段课程：
    阶段1（0-30% episodes）：只用证候要素数 ≤ 2 的病例
    阶段2（30-60% episodes）：证候要素数 ≤ 4
    阶段3（60-100% episodes）：全量数据

但sample_f1仅微涨0.0049，仍然差于HistGB 0.0212。原因如下：

【根因1】🔴 高频标签上的"精度-召回权衡"恶化
  - 旧DQN precision=0.9275，新DQN precision=0.8990（-0.0285）
  - 旧DQN recall=0.8584，新DQN recall=0.8839（+0.0255）
  - 新DQN用精度换取了召回，但precision下降幅度大于recall上升幅度
  - 这意味着新DQN虽然覆盖了更多真实标签，但也推荐了更多错误标签
  - avg_selected从3.27升至3.47（+0.2），更接近真实均值3.56，但错误推荐也在增加
  - 根因：Noisy Nets + 课程学习让模型更"大胆"，但也更容易"误选"

【根因2】🔴 低频标签的"全或无"困境
  - HistGB/RF对脾阳虚(4样本)、肺气虚(2样本)、肺阳虚(2样本)的F1=1.0
  - 新DQN对这些标签F1=0（完全无法预测）
  - 原因：树模型天然支持小样本——只要训练集中出现过的标签组合，就能泛化
  - DQN的RL机制需要多次见到相同(symptom, partial_selection, reward)才能学到
  - 低频标签的(s,a,r,s')在replay buffer中出现频率极低，TD学习难以收敛
  - 这解释了macro_f1差距0.3249的绝大部分

【根因3】🔴 树模型的"死记硬背"优势在辨证场景中天然成立
  - 中医辨证本质是模式匹配：症状集合→证候要素集合
  - 训练集中出现过的症状组合，测试集中大概率重复出现
  - 树模型只需记住训练集中的标签组合即可获得高F1
  - 但DQN被强制"逐步骤"决策，在每一步都可能犯错，错误累积
  - 这是RL框架本身的根本性劣势

【根因4】🔴 potential-based奖励塑形的局限性
  - 当前奖励=delta_F1_after_selection - baseline，鼓励每一步提高F1
  - 但F1是非线性、非可加的指标——选择"气虚"后再选"血瘀"的边际F1增益，
    取决于当前已选集合与ground truth的精确关系
  - 潜在函数无法完美捕捉这种复杂交互
  - 相比之下，树模型直接输出多标签概率，没有"步骤分解"问题

【根因5】🟡 课程学习带来正向但有限的改善
  - exact_match从0.507→0.573（+13%）说明课程学习确实有效
  - 但课程学习只改善了"选择正确数量标签"的能力
  - 并未改善"选择正确标签内容"的能力
  - cardinality_error从0.511→0.357（-30%）印证了这一点

【根因6】🟡 Noisy Nets + epsilon-greedy 双探索机制可能过度探索
  - Noisy Nets本身已提供状态依赖的探索噪声
  - 再叠加epsilon=0.08→0.005的随机探索
  - 在课程学习初期（len≤2阶段），样本只有308个，探索噪声可能过大
  - 导致模型在简单样本上也没有充分利用已学到的预训练知识

11.4 新DQN vs 传统方法 综合评分
================================================================================

| 维度               | 新DQN  | 最佳传统 | 胜负 | 说明 |
|--------------------|--------|---------|------|------|
| 高频标签(support>100) | ★★★★ | ★★★★   | 接近 | 气虚、血瘀、气滞F1接近 |
| 中频标签(10-100)     | ★★★   | ★★★★   | 落后 | 寒凝差-0.09，热蕴差-0.02 |
| 低频标签(<10)        | ★     | ★★★★   | 惨败 | DQN几乎无法预测 |
| 标签数量准确性       | ★★★★ | ★★★★   | 接近 | cardinality_error仅差0.027 |
| 完全匹配             | ★★★   | ★★★    | 接近 | 0.573 vs 0.617 |
| 可解释性             | ★★★★ | ★★     | 🟢胜 | 逐步骤决策过程天然可解释 |
| 动态决策             | ★★★★ | ★      | 🟢胜 | 传统方法无法模拟"诊断过程" |

结论：DQN在"决策过程可解释性"上有独特优势，但在纯预测精度上始终不如树模型。
这是RL框架本身的固有局限，而非调参问题。

11.5 更新后的改进路线图（v3）
================================================================================

基于三轮实验的经验，重新审视改进方向：

已完成的改进（效果有限）：
  ✅ soft target update —— 恢复precision但sample_f1仅微涨
  ✅ 低学习率 2e-4 —— 减轻灾难性遗忘但未根治
  ✅ aux权重衰减 0.5→0.05 —— 与课程学习配合，改善exact_match
  ✅ Noisy Nets —— 状态依赖探索，但可能与epsilon冲突
  ✅ 课程学习 —— 改善数量准确性，exact_match +13%
  ✅ Multi-step n=3 —— 加速奖励传播
  ✅ 预训练锚点正则 —— 保留预训练知识

当前瓶颈分析：
  1. RL框架的"逐步骤决策" vs 树模型的"直接输出"——这是根本性的范式差异
  2. 低频标签的样本不足——RL需要更多交互数据
  3. F1的非线性不可加性——potential函数无法完美捕捉

下一步建议（按优先级）：

A. 【紧急·高收益】减少Noisy Nets与epsilon的双重探索冲突
   → 方案：Noisy Nets模式下，epsilon改为0.02→0.0（极小探索）
   → 预期：恢复precision约0.01-0.02，sample_f1可达0.89+

B. 【重要】对低频标签使用"专家模板"硬编码
   → 方案：对于support<5的标签，在RL输出后叠加规则层
   → 例如：如果症状包含"便溏+乏力+舌淡"，强制添加"脾气虚"
   → 预期：macro_f1可提升至0.5+，同时不影响高频标签

C. 【探索性】尝试端到端监督学习+RL混合训练
   → 方案：不是"预训练→RL"，而是交替训练
   → 每个episode: 1步监督学习 + 1步RL
   → 监督学习持续提供ground truth信号，防止RL漂移

D. 【学术价值】保留当前RL框架的"过程可解释性"优势
   → 在论文中强调：DQN的sample_f1虽略低于树模型，但提供了"诊断推理过程"
   → 这是传统黑盒模型无法提供的独特价值
   → 如果你的论文核心贡献是"可解释的诊断决策过程"，而非"最高精度"，
     那么0.8839 vs 0.9051的差距是可以接受的

E. 【如果必须追平精度】考虑放弃RL，改用Set Transformer等集合预测模型
   → 集合预测天然适合"症状集合→证候要素集合"的映射
   → 不涉及序列决策，避免错误累积
   → 但会失去"诊断过程可解释性"

11.6 关键结论
================================================================================

1. 综合改进（低LR + soft update + Noisy Nets + 课程学习 + n_step + aux衰减）
   使 exact_match +13%, macro_f1 +247%, cardinality_error -30%，改善显著

2. 但 sample_f1 仅从0.8790→0.8839（+0.5%），几乎原地踏步
   说明这些改进改善的是"次要指标"，核心指标已触及RL框架的天花板

3. 新DQN与HistGB的sample_f1差距=0.0212，约2.3%
   这个差距很可能无法通过调参消除——因为RL的逐步骤决策 vs 树模型的直接输出
   是根本性的范式差异

4. 建议论文策略：不追求在F1上超越传统方法，而是强调DQN提供的
   "可解释的序贯诊断决策过程"是传统方法无法实现的独特优势

5. 如果审稿人要求追平传统方法的F1，可以考虑方案B（低频标签规则增强）
   或方案E（改用集合预测模型）
